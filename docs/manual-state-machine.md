# Vim-mode state machine

This is the behavior contract for both Omarchy and macOS. The daemon makes
the decisions; Hyprland and Hammerspoon only forward keyboard notifications
and display `status --bar`. Changing platforms must not change these rules.

## Host control states

| Control state | Meaning | Indicator |
|---|---|---|
| Automatic | No override; follow the focused editor. A plain terminal without a client is off. | NORMAL, INSERT, VISUAL, CMDLINE, RAW, VIM for legacy, or hidden for off |
| Manual tracking | Follow editor reports; when the automatic result is off **without a reporting client**, use legacy so the keyboard can infer modes. An explicit client `off` stays off. | Editor mode when available, otherwise VIM |
| Disabled | An off override suppresses current-editor reports and survives application focus changes. | Hidden, never RAW or VIM |

Manual tracking is an override policy, not an additional LED mode. Its legacy
fallback is code 4 and reads **VIM**, not MANUAL. The tooltip/status distinguishes
manual tracking from forced legacy. Automatic plugin-less editor detection can
also select legacy, independently of manual tracking. `set legacy` forces
keyboard-side inference even when an editor reports a mode; `set manual` keeps
following those reports.

Manual tracking uses the existing editor-mode LED codes. Its fallback writes
code 4 (Scroll Lock on, Kana and Compose off; HID byte `0x04`). A legacy
reassertion uses code 7 (all three on; `0x1c`) without repeating Esc. See the
[complete wire-code table](../README.md#the-codes-on-the-wire).

## Transitions

| Event | Result |
|---|---|
| Daemon starts | Automatic; overrides are in memory, not persisted |
| Enable combo: Hyper+F20 | `set manual --no-toggle`; replaces disabled with manual tracking |
| Disable/leave notification: Meh+Esc | `set off --sticky --no-toggle`; enters disabled |
| Repeat either notification | Confirms the requested state; never toggles it away |
| Normal/insert/visual/cmdline/raw report in automatic or manual tracking | Follow the reporting editor, including RAW in pickers, terminal jobs and pending leaders |
| Mode/focus update from an already known Neovim while disabled | Remain disabled |
| Same Neovim reconnects or resends hello while disabled | Remain disabled |
| A new Neovim session connects while disabled | Clear off override; return to automatic tracking |
| Non-Neovim client connects while disabled | Remain disabled |
| Application changes during manual tracking | Clear the non-sticky manual override; return to automatic tracking |
| Application changes while disabled | Remain disabled |
| `set auto` | Clear any override; return to automatic tracking |

The keyboard enable notification creates a non-sticky manual override. An
application identity change (known/unknown focus, application class, or PID)
clears it; switching windows within the same application class and PID does
not. CLI callers may request `--sticky` to retain manual tracking across
application changes.

A new session is a new Neovim process, identified by PID plus an opaque token
generated by the plugin. The token survives socket reconnects and plugin module
reloads; a reused OS PID with a different token is a new session. Older plugins
that omit the token use PID-only compatibility, which cannot distinguish PID
reuse. New-session detection happens on hello, not on each keystroke or focus
change. It clears only off overrides, not explicitly forced legacy/raw/other
modes. A session connecting in the background still clears off; the focused
application then determines the automatic result.

## Platform adapters

| Platform | Enable binding | Disable binding | Decision logic |
|---|---|---|---|
| Omarchy/Hyprland | Hyper + `code:198` (physical F20: evdev 190 + 8) | Meh+Esc | Shared daemon |
| macOS/Hammerspoon | `cmd+alt+ctrl+shift`, `f20` | `alt+ctrl+shift`, `escape` | Shared daemon |

Both send the identical commands in the transition table. Linux's XKB maps
physical F20 to `XF86AudioMicMute`, so a symbolic Hyprland `F20` binding misses
the notification. The Linux legacy Hyper+Esc binding supports older firmware.
macOS reserves Cmd+Opt+Esc for Force Quit; it cannot serve as the enable chord.
F13 was also rejected because it controls brightness on the owner's Mac.

## Validation and troubleshooting

**Manual platform validation:** the maintainer confirmed validation on both
Omarchy and macOS on 2026-10-27. Native macOS validation is complete.

**Previously recorded Omarchy checks:** physical F20 chord dispatch, real Neovim UI startup,
Normal/Insert tracking, hidden indicator after disable, same-process reconnect
staying disabled, and new-process startup restoring Normal and the indicator.

**Validated in portable tests:** Hammerspoon forwards the same commands and
refreshes/hides its item; the shared daemon implements the lifecycle; plugin
session identity survives a real socket reconnect. Portable tests complement
the manual platform validation; they do not establish that a particular
installed copy is current.

Use this checklist when upgrading or diagnosing a macOS installation:

1. Update the checkout to the intended release or **main**, then run
   `make install` there. The generic remote installer defaults to the latest
   release; use **main** when diagnosing changes not yet released.
   The Spoon is embedded in the binary: copying source alone or running an old
   binary's `install --hammerspoon` can reinstall an old Spoon. The installer
   attempts to reload Hammerspoon; confirm a reload actually occurred.
2. Update the separately managed Neovim plugin too (for Lazy: `:Lazy update
   zmk-vim-mode`), then start a new Neovim process. The daemon checkout, installed
   executable, installed Spoon and Lazy-managed plugin are distinct copies.
3. Run `zmk-vim-mode doctor`. Confirm macOS Input Monitoring and Accessibility
   grants for the installed daemon, plus Hammerspoon's required Accessibility
   access. Inspect Hammerspoon's console for load/hotkey/task errors.
4. Confirm the installed Spoon binds **f20**, sends **set manual --no-toggle**,
   and resolves the expected executable/socket. Use `status --json` to inspect
   `override`, connected `clients`, focus and `ax_trusted`; use `status --bar`
   to distinguish a daemon decision from a rendering problem.
5. Test this sequence with the editor focused: fresh Neovim → NORMAL; `i` →
   INSERT; Escape → NORMAL; disable → hidden; further mode changes and a
   same-process plugin reconnect → still hidden; quit and start a new Neovim
   → NORMAL again. Then enable in a plain terminal → VIM; disable → hidden.
   Repeated enable/disable notifications must remain idempotent.
6. If automatic tracking works but enable does not, inspect macOS F20 delivery
   and the Spoon before changing the shared state machine or reflashing again.
   If a new Neovim is blocked, check for a stale daemon/plugin and the off
   override before blaming the menu-bar item.

Keep the semantic contract above fixed while diagnosing a platform adapter.
